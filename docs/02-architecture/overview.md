# 아키텍처 개요

## 한 문장

**게임 전체가 Phaser 없이 돌아가고, 씬은 그 결과를 그리기만 한다.**

## 두 개의 층

```
src/game/     순수 TypeScript. Phaser import 금지. 게임의 전부.
src/scenes/   Phaser. 입력 수집과 그리기만. 판정 없음.
```

`src/game/world.ts`의 `stepWorld(world, dt, steer)`가 경계다. 씬은 매 프레임 이 함수를 부르고,
돌려받은 결과(점수·레벨업·충돌)를 화면에 반영한다. 그래서 120초짜리 주행 전체를 브라우저 없이
밀리초 단위로 시뮬레이션할 수 있고, 실제로 `tests/world.test.ts`가 그렇게 한다.

## (x, s) 좌표계

충돌과 배치는 **화면 좌표를 쓰지 않는다.**

- `x` — 가로 위치 (논리 좌표 0..480)
- `s` — 출발점부터의 주행 거리. 단조 증가하며, 이것이 곧 진행도다

화면 y는 그릴 때만 파생된다: `screenY = LAYOUT.carScreenY - (s - carS)`. 차는 화면에서 위아래로
움직이지 않고, 세계가 내려온다. 덕분에 충돌 판정이 카메라와 무관해지고, 테스트가 렌더링이 아니라
기하로 읽힌다.

## 도로가 튀지 않는 이유

중심선을 `sin(주기 × s)`로 계산하면 레벨이 주기를 바꾸는 순간 도로가 옆으로 순간이동한다 —
`s`가 수만일 때 주기가 0.0006만 달라져도 sin의 인자가 라디안 단위로 뛴다.

그래서 `TrackNode`는 **적분된 위상**(`phase`)을 들고 다닌다. 주기 변화는 인자의 *미분*만 바꾸고
인자 자체는 건드리지 않는다. 여기에 중심선·폭 모두 비율 제한 추종(`approach`)을 걸어, 레벨업이
계단이 아니라 활강이 되게 한다. 같은 제한이 도로의 최대 기울기(`TRACK.maxSlope`, 약 29°)로도
쓰이고, 이 값은 "차가 도로를 앞지를 수 있는가"라는 부등식으로 `tests/config.test.ts`에 묶여 있다.

## 지금의 파라미터 vs 저기의 파라미터

트랙은 화면 한 장만큼 앞서서 생성된다. 그래서 파라미터를 두 곳에서 다르게 읽는다:

- **기하와 밀도**는 `paramsForLevel(levelFor(그 노드의 s))` — 그 지점의 난이도
- **스크롤 속도**는 차의 현재 레벨 — 속도는 장소가 아니라 "지금"의 속성이다

섞으면 난이도 변화가 반 화면씩 밀리거나, 도착했을 때의 속도와 앞의 지형이 어긋난다. 이 설계에서
가장 넣기 쉬운 버그라 양쪽에 주석이 달려 있다.
