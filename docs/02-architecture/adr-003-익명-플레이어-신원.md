# ADR-003: 로그인 없는 익명 플레이어 신원

## 상태

승인됨 (2026-09-12)

## 배경

점수에 "누가 냈는지"를 붙이고 싶다. 그렇다고 이메일·비밀번호 로그인을 만드는 것은 캐주얼 웹게임에
과하고, GitHub Pages는 정적 호스팅이라 세션을 유지할 서버도 없다.

필요한 것은 "이 단말에서 접속하면 그 사람으로 인식"되는 수준의 약한 신원이다.

## 결정

**첫 방문 시 이름을 입력받고, uuid와 이름을 쿠키에 저장한다.** 쿠키가 있으면 그 사람으로 보고
게임을 바로 시작한다.

```
cookie: player = {"id":"<uuid>","name":"동혁"}   path=/, max-age=400일, SameSite=Lax
```

- `src/services/player.ts` — 신원 저장·복원. 이름 정규화와 인코딩은 순수 함수로 분리해 테스트한다.
- `src/ui/nameGate.ts` + `index.html` — 첫 방문 이름 입력 오버레이. Phaser 씬이 아니라 DOM이다.
- `main.ts` — `await ensurePlayer()` 후에 게임을 부팅하고, `player`를 registry에 넣는다.
- `ScoreService.submit(score, player)` — 점수를 낸 사람을 함께 받는다.
- `LocalScoreService` — `<id>.best`에는 **숫자만**, 기록자는 `<id>.best.owner`에
  `{id, name}`으로 따로 저장한다. 개명하면 `renameOwner()`가 **같은 id일 때만** 이름을 갱신한다.
- `UIScene` — HUD에 `이름 · 최고 N`을 표시하고, 신기록이 나오면 그 자리에서 저장한다.
  **HUD의 이름을 탭하면 같은 오버레이가 변경 모드로 열린다.**

**쿠키 외에 localStorage 미러를 같이 쓴다.** 읽을 때는 쿠키 → 미러 순이고, 미러에서 복원하면
쿠키를 다시 굽는다.

## 이유

**쿠키를 1차 저장소로 쓴 이유**: 나중에 서버 랭킹을 붙이면 신원이 요청마다 자동으로 실려 가는
편이 낫다. localStorage는 코드가 직접 실어 보내야 한다.

**그런데도 localStorage 미러가 필요한 이유**: Safari(iOS·macOS)는 **스크립트가 만든 쿠키의 수명을
7일로 제한**한다. 쿠키만 쓰면 일주일 쉬었다 돌아온 플레이어가 첫 방문자로 보이고, 이름을 다시
묻게 된다. 둘 다 지워질 수는 있지만 동시에 지워지는 경우는 드물어서, 서로를 복구해준다.
(실제 브라우저에서 쿠키를 지우고 새로고침해 복구되는 것을 확인했다.)

**이름 입력을 Phaser가 아니라 DOM으로 만든 이유**: 캔버스에는 텍스트 입력이 없고, 한글은 IME가
`<input>`에 조합해 넣어야 한다. Phaser로 흉내 내면 한글 입력이 깨진다.

**`<id>.best`에 이름을 섞지 않은 이유**: 게임 포털이 이 키를 `Number(raw)`로 읽는다(ADR-002).
JSON으로 바꾸면 포털의 점수 표시가 조용히 깨진다. 그래서 값은 숫자로 두고 이름은 형제 키로 뺐다.

**`submit()`이 player를 인자로 받는 이유**: 서버 구현체는 요청 본문에 id와 이름이 필요하다.
서비스가 스스로 쿠키를 읽게 하면 저장소 의존이 서비스 안으로 숨어들어, 교체 지점이 `main.ts`
한 곳이라는 원칙이 깨진다.

**핑거프린팅을 쓰지 않은 이유**: 삭제해도 남는 식별은 동의 없는 추적에 가깝고, 브라우저 업데이트나
사설 브라우징에서 값이 흔들려 신뢰도도 낮다.

## 영향

- **신원은 인증이 아니다.** id·이름 모두 devtools에서 바꿀 수 있다. 서버 랭킹을 붙일 때 이 값만
  믿고 권한을 주면 안 되고, 치팅은 별도로 다뤄야 한다.
- **기기·브라우저마다 다른 사람이 된다.** 폰과 PC의 기록은 합쳐지지 않는다. 합치려면 복구 코드
  입력이나 패스키 같은 수단이 추가로 필요하다.
- **쿠키는 매 요청 헤더로 github.io에 전송된다.** 이름은 사용자가 직접 입력한 별명이므로 실명을
  넣지 않도록 안내 문구를 "이 기기에서 점수를 기록할 이름"으로 두었다.
- **신원은 오리진 전체가 공유한다(`path=/`).** 게임별로 분리되는 점수 키와 정반대다. 포털과 모든
  게임이 같은 플레이어로 인식하는 것이 의도이며, 포털도 같은 쿠키를 읽어 이름을 보여줄 수 있다.
- **개명해도 기록은 유지된다.** uuid가 그대로이므로 최고 점수도, 그 기록의 이름도 따라온다.
  다만 갱신되는 것은 **그 게임의** `.owner`뿐이다. 다른 게임의 `.owner`는 각 게임을 다시 열
  때까지 예전 이름을 들고 있다. 어차피 화면에 쓰이는 이름은 쿠키의 현재 이름이라 눈에 띄지 않는다.
- 기록자를 이름이 아니라 `{id, name}`으로 저장하는 이유는 개명과 "같은 기기의 다른 사람"을
  구별하기 위해서다. id가 다르면 그 기록의 이름은 건드리지 않는다.
