# ADR-002: 점수 저장 키를 게임 id에서 도출

## 상태

승인됨 (2026-09-12)

## 배경

`LocalScoreService`는 최고 점수를 `game.best`라는 고정 키로 localStorage에 저장했다.

```ts
const BEST_KEY = 'game.best';
```

모든 게임은 `https://y3games.github.io` **한 오리진** 아래 GitHub Pages로 배포된다. localStorage는
오리진 단위로 공유되므로, 이 템플릿에서 만든 게임이 두 개 이상 배포되는 순간 서로의 최고 점수를
말없이 덮어쓴다. 증상은 "점수가 가끔 이상하다" 정도라서 원인이 저장 키라는 걸 알아채기 어렵다.

MergeDrop은 이 문제를 `mergedrop.best`로 피해 갔고, 게임 포털은 `<게임 id>.best` 규약으로 각
게임의 최고 점수를 읽는다. 즉 규약은 이미 있었고 템플릿만 따르지 않고 있었다.

## 결정

키를 하드코딩하지 않고 **게임 id에서 도출**한다. id는 `main.ts`에서 주입한다.

```ts
// src/main.ts
const GAME_ID = 'phaser-starter'; // 새 게임에서는 저장소 이름으로 교체
const scoreService: ScoreService = new LocalScoreService(GAME_ID);
```

- `LocalScoreService`는 생성자에서 받은 id로 `<id>.best` 키를 만든다.
- id가 슬러그(소문자·숫자·하이픈)가 아니면 생성자가 즉시 throw 한다.
- README와 CLAUDE.md에 "새 게임을 만들면 `GAME_ID`를 바꿀 것"을 명시하고, 포털이 읽는
  `<id>.best` 규약을 함께 적었다.
- 키 도출과 게임 간 분리를 `tests/localScoreService.test.ts`로 고정했다.

## 이유

**전체 키가 아니라 게임 id를 받는 이유**: 생성자가 `'mergedrop.best'` 같은 완성된 키를 받으면
접미사를 빠뜨리거나 `.score`처럼 제각각인 키가 생길 수 있다. 포털은 `<id>.best`만 읽으므로,
id만 받아 접미사는 서비스가 붙이는 편이 규약을 코드로 강제한다.

**`config.ts`가 아니라 `main.ts`에 두는 이유**: `config.ts`는 밸런스·레이아웃 튜닝 값만 담는
파일이고, 게임 id는 튜닝 값이 아니라 **조립 정보**다. `main.ts`는 이미 `ScoreService` 구현체를
고르는 유일한 주입 지점이므로, 저장 위치에 관한 결정이 한곳에 모인다.

**빌드 시점에 자동 도출하지 않은 이유**: `base`처럼 `GITHUB_REPOSITORY`에서 뽑는 방법도 있다.
그러나 로컬 개발에는 그 변수가 없어 dev와 배포본의 키가 달라지고, 저장소 이름을 바꾸면 기존 점수가
조용히 사라진다. 점수는 사용자 데이터라 자동 도출보다 명시가 낫다.

**잘못된 id에서 throw 하는 이유**: 대문자나 공백이 섞인 id는 조용히 엉뚱한 키에 쓰이고, 포털은
점수를 찾지 못한다. 부팅 시 바로 터지면 개발 중에 반드시 발견된다.

## 영향

- **템플릿에서 만드는 새 게임은 `GAME_ID` 교체가 필수 작업이 됐다.** 안 바꾸면 이미 배포된
  템플릿 데모(`phaser-starter`)와 키가 겹친다. README·CLAUDE.md·`main.ts` 주석 세 곳에 적어 두었다.
- **이미 배포된 phaser-starter 데모의 기존 점수(`game.best`)는 버려진다.** 재배포 후 사용자는
  0부터 다시 시작한다. 데모라서 감수한다.
- **포털의 `scoreKey: 'game.best'` 예외는 재배포 전까지 유지해야 한다.** 배포본이 아직 옛 키를
  쓰고 있으므로 지금 예외를 지우면 포털이 점수를 못 읽는다. 재배포 후에 제거할 것.
- 게임 id가 저장소 이름·포털 카탈로그 id와 같아야 한다는 암묵적 결합이 생겼다. 세 값이 어긋나면
  게임은 정상 동작하지만 포털 카드의 최고 점수만 비어 보인다.
